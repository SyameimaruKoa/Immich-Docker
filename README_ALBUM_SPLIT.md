# アルバムの縦・横・正方形への分割

指定した Immich アルバムを個別に `元名_縦`・`元名_横`・`元名_正方形` に分割します。画像と動画の両方を対象に、API の寸法・EXIF orientation（動画の回転も含む）から表示方向を判定します。メディア本体はダウンロードしません。正方形は独立したアルバムに分類し、0件の分割先は作成しません。

既存の未分類同期スクリプトのAPIクライアントを流用します。接続先はこのホストの `http://127.0.0.1:2283/api` 固定で、スクリプトと同じ場所の `.env` の `IMMICH_API_KEY` を使います。Docker Compose が必要です。APIキーには `user.read`, `asset.read`, `album.read`, `album.create`, `albumAsset.create`, `album.delete` が必要です。`--keep-source` 使用時は `album.delete` は不要です。

```bash
# 作成先名、分類件数、追加件数、元アルバムの削除予定だけを確認
./immich-album-split.sh --dry-run '旅行*' '家族'
# 各アルバムを個別に分割し、全件確認できた元アルバムを削除
./immich-album-split.sh '旅行*' '家族'
# 元アルバムを保持して分割
./immich-album-split.sh --keep-source '旅行*'
```

名前は大文字小文字を区別し、`*`・`?`・`[abc]` のワイルドカードに対応します。シェルで展開されないよう引用符で囲んでください。複数指定やパターンの重複でも同じアルバムは一度だけ処理します。再実行時の多重分割を避けるため、名前が `_縦`・`_横`・`_正方形` で終わるアルバムは対象外です。これらが元の名前に含まれる場合は先に改名してください。一致なしや同名の元アルバム・分割先が複数ある場合はエラーになります。

共有アルバム（他ユーザー所有を含む）も対象です。新規分割先ではユーザー共有と各ユーザーの権限を引き継ぎます。他ユーザーが元所有者の場合は、その人を編集者として追加します。共有リンクは再作成しません。同名の分割先が既にある場合は、その共有設定を維持して不足分だけ追加します。追加権限がない分割先は事前にエラーにします。共有アセットの追加権限はサーバーの判定に従い、失敗時は元アルバムを保持します。他ユーザー所有の元アルバムは削除せず保持します。

元アルバムの削除は既定で有効です。全件取得を件数で確認し、全アセットを分類・追加して分割先への所属を再確認した後、元アルバムに変更がないことを再確認して削除します。削除するのはアルバムで、画像・動画本体は削除しません。寸法不明・未対応の回転情報・ゴミ箱のアセットがある場合と空アルバムは保持します。読み取り失敗時は書き込み前に停止し、追加・確認の失敗時も元アルバムを削除しません。途中まで作成・追加された分割先は残り、再実行で不足分を追加できます。

サーバーの処理はトランザクションではないため、実行中のアルバム編集は避けてください。確認直後の同時編集を完全には防止できません。同じAPIキーでの分割の重複起動はComposeの共有ロックで防ぎます。未分類同期とは別ロックのため同時実行を避けてください。dry-run は読み取りのみで、サーバーへの実際の追加・削除権限を完全に検証するものではありません。

```bash
python3 -m unittest discover -s tests -v
```

API仕様: [searchAssets](https://api.immich.app/endpoints/search/searchAssets)、[getAllAlbums](https://api.immich.app/endpoints/albums/getAllAlbums)、[deleteAlbum](https://api.immich.app/endpoints/albums/deleteAlbum)。既存スクリプトと同じ Immich v3 の `albumIds` / `page` 検索を使います。
